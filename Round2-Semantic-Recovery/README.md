## 1. What this round does

The Social Engine's comprehension layer has to read a social-media post and recover two things:

- **`sentiment_label`** (Negative / Neutral / Positive, perfectly balanced, 3,000 each) — the primary task. Headline metric: **macro-F1**.
- **`topic_category`** (4 classes, 86% one class) — a secondary task. We found these labels were generated by a fixed substring-keyword rule rather than genuine topic meaning (see [Finding: topic labels are spurious](#4-key-findings)), so they're reproduced with a rule-based classifier rather than modelled.

**Selected model (sentiment):** a weighted ensemble —

```
p̂ = 0.25 · p(tfidf+char LogReg) + 0.20 · p(MiniLM embeddings + LogReg) + 0.55 · p(fine-tuned MiniLM)
```

chosen by grid search on the validation split, before the test set was touched.

**Test-set result:** macro-F1 **0.7178** (95% CI [0.691, 0.741]), accuracy 0.7173, n = 1,185 — a statistically significant +0.0935 macro-F1 improvement over the strongest classical baseline (McNemar p = 3.0×10⁻¹⁰).

## 4. Key findings

1. **Deduplicate before splitting, or your score is a lie.** Only 7,900 of the 9,000 rows are unique text; a naive random split leaks duplicate posts across train/test and inflates macro-F1 by **7.7 points** (0.6605 naive vs. 0.5832 grouped 5-fold CV). Every model in this round is trained/evaluated on the deduplicated 7,900-row set, split 70/15/15 with an explicit no-leakage assertion.
2. **Neutral is the hard class.** Recall 61.2%, the lowest of the three, and it's the class involved in >87% of all test-set errors — it's defined by the *absence* of polarised vocabulary rather than by vocabulary of its own, so lexical models systematically over-predict polarity on factual/reporting-style or idiomatic Neutral posts.
3. **Topic labels are spurious, not semantic.** A fixed, ordered substring-match rule (`app`, `down`, `update`, ... → Technical_Issues; etc.) reproduces all 9,000 topic labels exactly. 44–88% of triggers per class fire *inside* unrelated words (`happy` contains `app`, `band` contains `ban`). **These labels should not be used for topic-based routing as-is** — they need relabelling with a genuine topic model first.
4. **The ensemble is calibrated.** Confidence buckets track observed accuracy closely across the board (e.g. 90%+ confidence → ~100% actual accuracy in this sample), so the model's own confidence score is trustworthy for routing low-confidence posts to human review.
5. **The learning curve hasn't plateaued.** Both fast candidate models were still improving at 100% of the training data — more labelled sentiment data would likely help further in Round 3.

Full detail, ablations, and the training methodology behind all of the above are in `Entropy_r2_technical_report.pdf`; test-set metrics and the error analysis alone are in `Entropy_r2_evaluation_metrics_report.pdf`.

## 5. Model artefacts (`model/`)

| File | What it is |
|---|---|
| `Entropy_sentiment_tfidf_logreg.pkl` | Word+char TF-IDF logistic regression component |
| `Entropy_sentiment_embedding_logreg.pkl` | MiniLM-embedding logistic regression component |
| `Entropy_minilm_sentiment_seed{42,7,1234}/` | Fine-tuned MiniLM weights, one directory per seed |
| `Entropy_sentiment_model.json` | Ensemble config — component weights, labels, file paths |
| `Entropy_topic_char_logreg.pkl` | Character-n-gram topic model — saved for comparison only, **not used for inference** |
| `Entropy_topic_rules.json` | The recovered substring rule set — used instead of the char-n-gram model for topic output |

Load and run inference with `SentimentEnsemble` from `Entropy_nlp_utils.py`:

```python
from Entropy_nlp_utils import SentimentEnsemble

model = SentimentEnsemble("model/")
model.predict(["your post text here"])
```

A reload test (loading every artefact fresh from disk and re-predicting on 200 held-out posts) matched the in-memory predictions on 100% of posts.

> **Submission note:** the fine-tuned MiniLM checkpoints are large transformer weights (tens of MB each), so the full ensemble doesn't fit a single-file, 10MB submission cap. Where a competition portal enforces that limit, only `Entropy_sentiment_tfidf_logreg.pkl` (plus, space permitting, `Entropy_sentiment_model.json` and `Entropy_topic_rules.json`) is uploaded as the representative artefact.
